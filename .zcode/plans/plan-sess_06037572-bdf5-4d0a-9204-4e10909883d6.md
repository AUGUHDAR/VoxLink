# VoxLink TURN 中继体系 实施计划（修正版）

## 架构定案
- **信令服务器（server-go）= 唯一总控**。Admin 新增"中继"板块 = TURN 服务器列表：每条填 名称 + 地址（IP / IP:port / 域名均可）+ 最大连接数 + 密钥 + 启停；增删改查即插即拔。
- **TURN/ 目录 = 三个完整独立的 TURN 服务器实现**，同一协议规范、协议严格一致：
  - `TURN/go/` —— Go 实现（Linux/Windows 服务器）
  - `TURN/php/` —— PHP CLI 实现（php-sockets 长驻进程，跑你的 PHP 设备）
  - `TURN/apk/` —— Android APK 实现（前台服务监听 UDP，跑你的安卓设备；公网入口由 frp 内网穿透提供）
  - 捐赠者拿任意实现 + 总控签发的密钥，部署后在 Admin 登记即可接入，**无限可插拔**。
- **客户端 = 唯一决策方**：测延迟、选节点；房主零 UI 零选择权，收到信令自动配合。
- **延迟探测用自研 UDP 应用层 PING/PONG**，与系统 ICMP ping 无关，禁 ping 不影响。

## 协议规范（先写，作为三个实现的共同契约）
`SPECS/turn-protocol-v1.md`：字节级定义 5 种 UDP 包——PING/PONG（限频）、BIND{sessionId, role, ticket}、DATA{sessionId, from→to}、KEEPALIVE、UNBIND。票据 = HMAC-SHA256(节点密钥, sessionId|roomCode|role|过期时间)，TTL 10 分钟，节点离线验签。节点每 10s 向信令 POST 心跳 {在线状态, 会话数, 字节数}（密钥鉴权），会话空闲 60s 回收。

## 一期：TURN 三个服务器实现（TURN/ 目录）
- `TURN/go/`：go.mod + main/protocol/session + config.json；交叉编译 win/linux amd64+arm64。
- `TURN/php/`：单文件 turn.php（纯 sockets 扩展，无 composer 依赖）+ config.json + systemd 样例。
- `TURN/apk/`：Android Gradle 项目（前台 Service + UDP socket + 配置界面 + 心跳）；代码完整交付，构建需 Android SDK（本机若无 SDK 则只做代码交付并注明）。
- `TURN/README.md`：三个实现各自的部署指南 + frp 配置样例 + Admin 登记流程（捐赠者视角也写清楚）。

## 二期：server-go 总控
- 新增 `relaynodes.go`：节点表存 `data.json["relay_nodes"]`（照 ai_moderation_models CRUD 模式）；心跳接收 + 30s 无心跳判离线；票据签发；容量扣减/归还；添加节点时自动生成密钥供复制。
- 端点：`GET /relay/status`（开关）、`GET /relay/list`（**硬限制：启用+在线+有余量节点最多下发 10 个**，`relay_list_max` 可调，防干爆客户端）、`POST /relay/allocate`（房间 token 鉴权 + 容量校验 + 签两张角色票据）、`POST /relay/release`、`POST /relay/node/heartbeat`（节点密钥鉴权）。
- Admin 页"中继"卡片：列表 + 添加（地址三种格式归一化）+ 行内改连接数/启停 + 删除 + 在线状态/连接数实时显示；走 AdminRequire + CSRF。
- 信号白名单加 turn_alloc / turn_release；cleanup 挂 runIfDue 清过期会话与离线节点标记。

## 三期：客户端（基准 fabric/1.20.2_1.20.6 → 锚点传播 25 模板）
1. 新文件 `network/TurnRelayClient.java`（整文件复制传播）：拉列表（≤10）→ 并行 UDP 测延迟（3 轮取最小，总超时 ~2.5s）→ 选最低延迟 → allocate → BIND/KEEPALIVE。
2. 平滑切换——ReliableUdpTransport 抽 UdpPath{socket, remoteAddress, 拆包头}：6 处发送点收敛统一 sender；第二接收线程喂同一序号空间（去重靠现有 nextExpectedSeq）；显式换路径 API。ConnectionManager 加 BackgroundPunchMonitor：TURN 期间后台并行两路各 5 分钟（低频直连 P2P 打洞 + 玩家中继尝试），任一成功且连续 K=20 探测稳定 → 切发送路径 → 10s 宽限可回退 → 宽限过 UNBIND + release；5 分钟都失败则停，退出重进重置。
3. UI：AttemptingJoinScreen 右上角"使用中继"按钮（20s 且 /relay/status 开了才显示；中途中断/失败也显示；分配期间置灰）；新增 voxlink.turn.* i18n × 13 语言。

## 四期：传播 + 构建验证
- sync 脚本（照 sync_relay113 模式：单行锚点、count==1 断言、CRLF 兼容、25 模板断言）传播客户端改动；新文件整拷。
- `build_all_versions.py` 全模板编译 + server-go 构建 + TURN/go 交叉编译（apk 按实际情况注明）。

## 并行分工（子代理）
先写协议规范 → 然后并行：TURN/go、TURN/php、TURN/apk、server-go 各一个子代理（全部以规范为契约）；客户端三期主线程做；四期收尾构建验证。

## 风险提示
UdpPath 双路径重构是最大块（估 800-1500 行新增），切换状态机需模拟丢包/半通场景测；一期二期先行即可独立上线（纯 TURN 硬中继已可用），平滑切换作为独立里程碑分步验证。
